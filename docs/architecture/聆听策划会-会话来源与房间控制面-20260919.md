# 聆听·策划会：会话来源与会议房间（2026-09-19）

后续阶段已完成多人语音通话代码及本机音频验证，见 [多人语音通话](聆听策划会-多人语音通话-20260919.md)。本文件保留房间控制面阶段的历史边界；生产仍未部署该功能。

## 已确认的产品范围

- 微信复用现有第三方登录，只提供统一账号身份；微信登录不授予通话音频权限。
- 自有会议房间参考腾讯会议的创建/加入流程，不依赖腾讯会议 SDK。
- 微信、腾讯会议、电话录音现阶段通过已有文件导入或系统分享入口进入 STT，不宣称直接读取第三方通话。
- 保留独立“聆听·策划会”，不替代“自定义会议”。遵循 simple and effective，房间入口位于该类型录音页的“更多”。

## 本阶段实现（源码完成，未部署）

| 能力 | 实现与边界 |
|---|---|
| 会话来源 | Room 数据库 26→27 增加音频来源、实际设备、外部会议编号、匿名分组数、首选采集输入。旧记录保留，未知来源不猜测 |
| 手机/蓝牙采集 | 来源弹窗选择手机或蓝牙麦克风；Android 12+ 请求附近设备权限并选通信设备，旧系统使用 SCO；记录实际路由，未走蓝牙时如实显示 |
| 外部文件 | 可标注导入音频、微信导出音频、腾讯会议导出音频、电话录音文件；使用既有系统文件选择/STT 链路 |
| 房间生命周期 | 创建、九位会议号加入、查看、重新加入、同意/撤回录音意愿、主持人结束、成员离开 |
| 账号隔离 | 复用账号登录会话；必须加入房间才能查看；退房即撤销可见性；删除账号级联清理成员及其主持房间 |
| Android 状态 | 账号或服务地址变化清空房间状态；前台显示弹窗时每 5 秒更新，后台/关闭停止轮询，操作期间不让旧轮询覆盖新状态 |
| 记录关联 | 录音页可明确把当前记录关联到一个已加入的开放房间；关联写入本机会议行并按 ownerId 校验，暂停后可解除/更换，录音中锁定关联 |
| 录音同意校验 | 开始/继续前重新拉取房间并校验开放状态、当前成员身份、所有在场成员同意；录音期间每 5 秒同步一次，成员撤回同意、本人离开、房间结束或同步失败会暂停本机采集与 STT |
| 纪要输入 | 有效片段保留时间范围和匿名说话人标签，补充实际来源上下文；无音频证据时不猜测情绪、音高、语速和沉默原因 |

房间存放在账户库的 meeting_rooms / meeting_room_members。schema 在服务启动时初始化，普通读取不抢写锁，数据库连接显式提交/回滚/关闭。客户端不新增一套房间凭据。

Android 数据库 27→28 增加可空的 `meetingRoomId`，旧记录默认不关联。该字段当前仅本机保存，尚未进入账户会议同步 API；不能据此宣称跨设备共享记录或云端归档已经完成。关联更新仅修改 ownerId 匹配行的这一列，不覆盖录音或转写字段。

## API

所有接口复用 Authorization 账号会话：

- GET /api/account/rooms：本人未离开的房间，优先展示开放房间。
- POST /api/account/rooms：创建。
- POST /api/account/rooms/join：凭九位会议号加入。
- GET /api/account/rooms/{id}：仅成员可见。
- POST /api/account/rooms/{id}/consent：更新本人录音意愿。
- POST /api/account/rooms/{id}/leave：成员离开；主持人先结束开放房间。
- POST /api/account/rooms/{id}/end：仅主持人，重复请求保持首次结束时间。

media_ready 固定为 false；all_recording_consented 是成员意愿汇总，不会单独触发麦克风、房间录音或 STT。只有用户在录音页显式关联当前记录后，录音生命周期才会使用这个同意校验；未关联的普通录音不发起房间请求。

## 未完成的范围与下一阶段

1. 自有实时音频：选择并部署 RTC/SFU 与必要的中继，完成双客户端通话、静音、重连、后台生命周期及多人压力测试；服务配置来自部署环境。
2. 房间 STT：每位成员独立音轨，服务端验证身份与录音同意，输出统一时间轴。账号音轨身份与模型匿名说话人标签必须区分，实时文字复用为纪要输入。
3. AI 互动与硬件：对话辅助需要独立的可取消请求和证据引用；当前仅有纪要生成规则，不是情绪识别模型。蓝牙采集代码仍需真实耳机验收，电话录音受系统/设备能力限制，不承诺可直接读取全部通话。

若任何在场成员拒绝或撤回录音同意，关联记录会在下一次同步进入暂停态，停止继续写入 PCM 和发送 STT；恢复前必须重新满足同意条件。监控由录音控制器持有，关闭弹窗或退到后台不停止监控。两次检查间隔 5 秒，单次房间 GET 有 5 秒传输超时；调度或正在执行的录音操作还会增加延迟，不承诺即时撤回。成员已离开时其原有的不同意状态不再阻塞其余成员。当前实现仍是单设备麦克风控制面，不是多人媒体层。

## 后续人工验收清单（部署后由用户执行）

1. 两个普通账号创建/加入同一房间；仅查看不会改变记录关联，点“关联本条记录”后重开页面能恢复。
2. 一个在场成员未同意时不能开始；全部同意后开始，实时转写与原有生成纪要流程保持不变。
3. 录音中撤回同意或结束房间；本机下次检查后暂停，通知和页面都显示原因；重新同意后手动继续。
4. 暂停后切换/解除关联；录音中不能改关联；新记录不会继承前一条记录的关联。
5. 关闭房间弹窗、退到后台和断网重试；普通未关联记录不受房间服务状态影响。
6. 手机/蓝牙输入分别验收，确认界面显示实际设备；耳机断连或不支持通话时不虚报蓝牙已接入。
