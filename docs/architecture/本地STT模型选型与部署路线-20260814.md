# 本地 STT 模型选型与部署路线

日期：2026-08-14

## 决策

- 默认主链路：Faster-Whisper `large-v3-turbo`，优先使用可用 GPU；无 GPU 仅在部署配置中显式选择较小模型。
- Windows 临时服务：RTX 3060 使用 CUDA `float16`，模型目录仍位于本机 `D:` 盘，不依赖网络共享目录。
- LS-Server 正式服务：Tesla V100 32 GB，CUDA `float16`；V100 不使用 BF16。
- 腾讯云：唯一保留的云端识别方案，作为用户手动选择或本地故障兜底。
- Qwen3-ASR-1.7B：保留为未来“文件导入高精度后台任务”候选，不进入实时主链路。
- Faster-Whisper `tiny/base`：当前不作为默认候选。

Android 默认仍选择 Faster-Whisper；模型名由本机服务的健康配置决定，当前 Windows 目标为 `large-v3-turbo`。AVD 调试包通过 `http://10.0.2.2:8888` 访问 Windows Host；Release/真机通过 `https://lstwin.space` 访问，并在域名存在 A 记录时严格走 IPv4 云端中继，PC 管理台仍可通过 AAAA 直连。Obsidian 只记录开发过程，不属于 App 功能。

## 本地优先与自动兜底（2026-08-17）

- 文件最终转写：`FallbackSpeechToTextEngine` 先调用本地 Faster-Whisper，失败后调用原腾讯云入口；成功的本地请求不会消耗腾讯额度。
- 实时流式转写：Android 默认连接本地端点；本地 WebSocket 在重连次数耗尽或鉴权/服务终止后，自动切换到 `https://118.25.43.185/stt-cloud`，每个录音会话最多自动切换一次，避免来回重试。
- 服务端流式推理连续三次异常会主动关闭本地流，确保客户端能够感知故障并触发云端兜底，而不是保持一个无文本的假连接。
- 配置版本 14 会把历史“托管腾讯云默认配置”迁移为本地 Faster-Whisper，同时保留腾讯云地址和账户令牌作为兜底；用户显式填写云端 API Key 的配置不被覆盖。
- Android Debug/AVD 继续使用 `http://10.0.2.2:8888`，Release 使用 `https://lstwin.space`；云端入口独立保存，不再把云端地址拼接到本地地址。
- Windows 临时节点当前目标配置为 `large-v3-turbo + CUDA float16`、`STT_MAX_CONCURRENT=1`，实时流与文件转写共用 GPU 模型，避免额外加载一份 CPU 流式模型。
- 2026-08-18 起本地模型面收敛为 Faster-Whisper 单一实现；腾讯云仍是唯一云端兜底。旧版 SenseVoice 配置升级时自动迁移到 `large-v3-turbo`，不会再创建 SenseVoice 引擎。

2026-08-17 实际验收：

- 模型文件大小为 `1,617,884,929` 字节，SHA-256 为 `e76620f83d5f5b69efd3d87e3dc180c1bd21df9fbebacfd4335e5e1efcc018da`，服务启动时校验通过。
- Windows 专用 runtime 使用固定版本 CUDA 12 cuBLAS/cuDNN 依赖，启动脚本只为 STT 子进程扩展 DLL 搜索路径，不修改系统级 PATH。
- `https://lstwin.space/health` 返回 `model=large-v3-turbo`、`device=cuda`、`model_loaded=true`、`model_checksum_verified=true`，流式预览模型同样已加载。

- 腾讯云健康接口保持 `cloud_asr.configured=true`、`realtime_asr.configured=true`，只作为本地故障兜底。
- Android 全量 Debug 单元测试与 APK 构建通过；服务端 STT 测试 `54` 项通过。验收时没有在线 ADB 设备，因此未执行本轮 AVD 覆盖安装。

## 产品命名与正式入口（2026-08-15）

Android 对外名称统一为：

| 技术实现 | 产品名称 | 角色 |
|---|---|---|
| Faster-Whisper | 智悟本地通用模型 | 默认主链路 |
| 腾讯云 ASR | 智悟增强云模型 | 用户主动选择或本地故障兜底 |

“本地”表示智悟本自托管、音频不提交第三方云 ASR，不限定模型必须运行在手机或局域网。当前 Windows 服务实际运行 Faster-Whisper `large-v3-turbo + CUDA float16`，管理台和服务端不再提供 SenseVoice 切换入口。

Android 构建入口已按 variant 隔离：Debug/AVD 默认使用 `http://10.0.2.2:8888`，Release 默认使用 `https://lstwin.space`。配置分别由 `MEETINGNOTES_STT_DEBUG_ENDPOINT` 和 `MEETINGNOTES_STT_RELEASE_ENDPOINT` 覆盖，旧 `MEETINGNOTES_STT_ENDPOINT` 仅作为 Debug 兼容项。配置版本 13 会在 Release 升级时清除遗留的 `localhost`、`127.0.0.1` 和 `10.0.2.2` STT 地址，避免历史 DataStore 覆盖正式入口。

`lstwin.space` 当前只有 AAAA 记录 `240e:390:494c:ec31:1ab:d4b7:f5d:d8eb`，没有 IPv4 A 记录。已通过公网 IPv6 实测 `/health` 与 `/ready` 返回 HTTP 200，Let’s Encrypt 证书受 Android 信任，Caddy 将 HTTPS/WSS 转发到本机 `127.0.0.1:8888`。因此它可作为当前 Release 数据入口，但纯 IPv4 网络仍无法访问，后续需要补充 IPv4 反向代理、隧道或双栈入口。

## 当前双端点架构（2026-08-15）

Android 不再把本地模型和腾讯 STT 假设为同一个服务根地址：

| 职责 | 当前入口 | 行为 |
|---|---|---|
| 本地优先 STT | AVD：`http://10.0.2.2:8888` | Faster-Whisper `large-v3-turbo`，负责实时预览和最终转写 |
| 云端兜底 STT | `https://118.25.43.185/stt-cloud` | 原云服务器腾讯标准 STT，只在用户主动选择或本地最终转写失败时使用 |

Android 配置分别保存 `localEndpoint` 和 `cloudEndpoint`。Faster-Whisper 只路由到本地入口，腾讯实时识别、文件识别、健康检查和额度查询只路由到云端入口。旧版把云端地址保存为 `localEndpoint/cloud-asr` 的配置会在配置版本 12 自动迁移。

录音中跨本地与云端切换时会重建 WebSocket。流式会话 ID 不跨服务器复用，切换后的最终稿改用完整录音上传。默认本地最终转写失败后才自动调用腾讯标准模型；本地成功时不产生腾讯调用和额度消耗。音频归档列表同时查询两个服务，并为每条音频保留实际所属服务地址。

Windows 本机服务只从受保护环境文件读取 App STT 访问令牌和账户令牌签名，不导入腾讯云凭据。本机 `/health` 已确认 `cloud_asr`、`realtime_asr` 均未配置；腾讯凭据只保留在原云服务器。

云服务器 Nginx 的 `/stt-cloud/` 反向代理到云端 STT 服务，并单独支持 `/stt-cloud/ws/transcribe-stream` 的 WSS 升级。该入口不依赖 Windows 工作站在线，因此本机故障时仍可兜底。

`lstwin.space` 已用于 Windows 本地 STT 管理面，访问根路径会跳转到 `/admin/`。入口由 Caddy 反向代理至 `127.0.0.1:8888`，通过 AliDNS DNS-01 使用 Let’s Encrypt 公网证书；证书续期不依赖公网 `80/443` 入站。管理页沿用受保护环境文件中的 Web 管理账号，提供服务状态、模型与设备信息、推理队列、实时会话、事件、日志和模型切换，不在源码或文档中保存凭据。

该域名现已作为 Android Release 默认 STT 数据入口，AVD 仍使用 `http://10.0.2.2:8888`。证书公网可信不等于所有网络均可达：当前只有公网 IPv6，工作站离线、IPv6 入站受限或手机处于纯 IPv4 网络时都会失败。`lstwin.cloud` 的权威 DNS 位于 DNSPod，当前独立使用 Caddy 本地 CA，不把该私有 CA 固化进正式 APK；后续仍需为 `lstwin.space` 补齐双栈或稳定反向隧道。

## 实测环境

样本取自 `\\Ls-server\!团队协同网盘\邓曙\本地音频\视频`，使用同一段 60 秒清晰中文，中文、VAD、最终稿 `beam=5`。

Windows 工作站：Intel i7-12700F、20 线程、RTX 3060 12 GB。

| 模型 | Windows 推理时间 | 结论 |
|---|---:|---|
| Faster-Whisper tiny / GPU FP16 | 6.85 秒 | 错词最多，不采用 |
| Faster-Whisper base / GPU FP16 | 4.61 秒 | 仍有明显错词，不采用 |
| Faster-Whisper small / GPU FP16 | 1.88 秒 | 速度与质量综合最佳 |
| Faster-Whisper base / CPU int8 | 2.88 秒 | 快，但精度低于 small |
| Faster-Whisper small / CPU int8 | 7.57 秒 | Windows 临时服务可用 |
| Qwen3-ASR-1.7B | 冷启动 53-63 秒；推理 38.69 秒 | 文本更准，但不适合实时主链路 |

`small + CPU int8` 的 60 秒中文样本 HTTP 总耗时约 9.3 秒；106.6 MB、20 分 20 秒的高密度英文视频耗时 336.4 秒。Windows 临时节点应按每小时音频约 10-17 分钟规划，实际受语速、静音比例与内容密度影响。CUDA 依赖补齐后可降到约 2 分钟/小时级别；当前不让正式服务依赖共享目录中的 CUDA/cuDNN DLL。

## 模型差异

Faster-Whisper `small` 示例：

```text
我们这个视频是C++教学,选职译。
6000字花了4分多钟。张语开桃和结尾检查。
```

Qwen3-ASR-1.7B 示例：

```text
我们这个视频是C加加教学，选直译。
六千字花了四分多钟。双语开头和结尾检查。
```

Qwen 对个别词更准确，但当前推理约为 Faster-Whisper `small` GPU 的 20 倍，且冷启动明显。它更适合未来不阻塞用户操作的离线高精度复核。

## IPv4 中继修复（2026-08-18）

`lstwin.space` 当前同时承担 IPv6 直连和 IPv4 中继：蜂窝 IPv4 -> 云服务器 `118.25.43.185` Nginx -> WireGuard `10.77.0.1/10.77.0.2` -> Windows Caddy -> STT `:8888`。此前 Nginx 没有转发 WebSocket `Upgrade`、`Connection` 头，导致 `/ws/transcribe-stream` 返回 404，管理台看不到 `session_open`。现已在 `edge-router/nginx-lstwin-frontdoor.conf` 的两个 HTTPS 反代位置补齐升级头，`nginx -t` 和 reload 通过。主域名 A+AAAA 均保留；Android STT 客户端通过 `Ipv4RelayDns` 固定使用 A 记录，PC 仍可 IPv6 直连。

云服务器自身强制 IPv4 健康检查返回 HTTP 200；带有效 STT 令牌的 WebSocket 握手返回 HTTP 101，并在 Windows STT 日志生成 `WebSocket accepted`。旧的“仅 AAAA、无 IPv4”描述属于 2026-08-15 历史验收，不代表当前入口状态。真实蜂窝网络仍需做一次用户侧回归。

## 长音频

本地文件上传总上限默认 1 GiB。106,570,924 字节 MP4 已实际通过 `/transcribe`，未出现 413。超过时长阈值的音频按 30 分钟片段和 3 秒重叠窗口处理，结果按顺序去重合并。腾讯云仍遵守其单次请求限制并使用独立分段策略。117 MB 级录音无需转给其他云厂商，也不需要在 Android 端切割。
