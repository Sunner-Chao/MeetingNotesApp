# 本地 STT 快速故障转移与 OTA 验证记录

日期：2026-08-19

## 目标

- 本地实时 STT 优先，连接异常时最多重试 3 次，每次间隔 1 秒。
- 本地链路在 3 秒恢复窗口内仍未获得新的服务端 `session_id`，立即触发腾讯云实时 STT 兜底。
- 录音生命周期不因识别链路切换而中断；用户始终看到当前识别路由和录音保存状态。

## 实现

- `StreamingSttClient` 增加本地恢复截止计时器、会话代次和恢复 epoch。旧连接的状态消息不能确认新连接，只有当前连接携带合法 32 位十六进制 `session_id` 才算就绪。
- 本地失败回调按录音会话去重，最多触发一次；恢复成功会取消截止计时器。腾讯云继续使用有界指数退避，最多 5 次。
- 录音状态新增 `LOCAL_RECOVERING`、`SWITCHING_TO_CLOUD`、`CLOUD_FALLBACK_ACTIVE` 和 `UNAVAILABLE` 等路由状态。
- Siri 和参考录音布局共用紧凑状态条，明确显示“本地连接波动”“正在转接云端识别”“云端识别已接管”和“录音仍在本机保存”。

## 验证

- `:app:testDebugUnitTest`：通过，包含 STT、录音会话和录音 UI 全量单元测试。
- `verifySigningConfig assembleRelease`：通过；debug/release 证书 SHA-256 为 `512a5cfb22ebd5330af75abeb5000b17025b12462e5207e6f9864f31fe78b77a`。
- AVD `My_Phone` 实测：`lstwin.space` 出现 `Connection reset` 后，约 3 秒内转接 `118.25.43.185` 腾讯云 WebSocket；页面显示“云端识别已接管 / 本地连接中断 · 录音未中断”，录音仍持续计时。
- Android `1.2.27`（versionCode `10227`）非 debuggable，APK SHA-256 为 `94cdabe4a1a651f13df12677c8ef6fadf259de86d014db5f1081b892ddf1bd99`。
- OTA 公网 metadata 返回 `10227`；`10227` 与上一版 `10226` 下载可用，`10225` 已按“仅保留最新与上一版”规则清理。

## 发布事故修正

Android-only 手动调用原子发布脚本时，临时文件初始由 root 创建，导致清单和新 APK 对 `meetingnotes` 服务账户不可读，公网短暂返回 204/404。已补回 `meetingnotes:meetingnotes`、0644 权限并复验 metadata、最新版摘要和上一版下载。部署脚本的标准路径仍通过 `--owner meetingnotes:meetingnotes` 发布。

## 边界

本记录只描述本地 STT、云端兜底和 Android OTA；不改变腾讯云作为唯一云端 STT 兜底的产品决策，也不把 Obsidian 暴露为 App 功能。
