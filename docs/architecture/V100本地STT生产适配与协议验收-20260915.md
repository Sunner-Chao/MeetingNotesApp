# V100 本地 STT 生产适配与协议验收

日期：2026-09-15

## 结论

V100（`DESKTOP-H3OE2CM`，4× Tesla V100 32 GB）承载 FunASR Paraformer Large：在线模型负责实时预览，离线模型配合 FSMN VAD 与 CT-Transformer 标点负责文件转写。GE4 AMD 与本机 Windows CUDA 服务均不恢复。

模型目录在 V100 的 `D:\LS-Models\modelscope\models`，服务目录为 `D:\LS-Project\meetingnotes-stt\service`。Windows 计划任务 `MeetingNotesApp-V100-STT` 负责开机启动和异常重启；环境文件为私有部署输入，不进入仓库。

## 协议修复

- Android 的 `Authorization: Bearer` WebSocket 握手和浏览器旧式首条 `authenticate` 消息均可用。
- `start` 返回 32 位 `session_id`，并返回 `stream_provider=local`，因此 Android 的本地/云端状态不会错位。
- 暂停会刷新缓存尾句，继续后恢复识别；整块音频后立即停止也会刷新延迟解码输出。
- 文件上传按流读取，超过容量立即返回 413 并删除临时文件。
- 账户令牌使用现有 Backend 的 `ACCOUNT_TOKEN_SECRET` 验证；诊断事件按账户隔离，不记录转写正文。
- 本地说话人分离尚未启用，健康接口明确返回 `models_present=false`、`active=false`，并预留 CAM++。

## 本机回环实测

使用 30 秒、16 kHz、单声道 PCM 基准音频，在 V100 主机本机回环执行：

| 指标 | Android 协议握手 | 浏览器兼容握手 |
|---|---:|---:|
| 握手 | 23.64 ms | 23.49 ms |
| 首次实时片段 | 992.93 ms | 1006.85 ms |
| 片段数量 | 73 | 74 |
| GPU 推理中位耗时 | 85.25 ms | 86.85 ms |
| 交付延迟 P50 / P95 | 96.20 / 102.90 ms | 96.63 / 104.07 ms |
| 停止排空 | 95.36 ms | 95.60 ms |
| 文件转写 | HTTP 200，3.543 s | HTTP 200，缓存后 0.328 s |

测试覆盖暂停/继续、尾句刷新、账户令牌校验和文件转写。Tailscale 当前经过 DERP，往返约 280–870 ms；因此公网链路延迟不能与以上模型回环指标混为一谈。

## 生产接入边界

V100 当前 Tailscale 地址不是普通手机公网入口。已建立 V100→VPS 的专用反向 SSH 通道（VPS 回环 `127.0.0.1:18889`），并将 VPS 的 `/stt-local` IPv4/IPv6 回源切换到该端口；原配置已保存在 `/var/backups/meetingnotes-v100`。由于 `lstwin.space` 在部分 IPv4 网络会被 DNS/web-block reset，Android Release 使用已有 IP 证书入口 `https://118.25.43.185/stt-local`，腾讯云继续使用 `/stt-cloud`。Pro `1.2.65/10265` 已完成固定签名 OTA 发布，服务器保留 `10265` 与 `10264`。
