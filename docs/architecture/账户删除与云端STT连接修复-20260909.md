# 账户删除与云端 STT 连接修复（2026-09-09）

## 结论

Lite 的新账户云端 STT 连接重置主要由移动网络访问同一域名的 IPv6 入口不稳定导致：构建默认曾指向 `auth.synthapi.asia`，而当前可用的账户和 STT 同源入口是 `lstwin.space`。账户 API、云端 STT HTTP/WSS 均固定使用 VPS IPv4 中继 `118.25.43.185`，同时保留 `lstwin.space` 的 TLS/SNI；新版本改用 `https://lstwin.space/api`，并在迁移时修正历史保存的旧主机；STT 仍使用 `https://lstwin.space/stt-cloud`，不改变腾讯云上游配置。

## 数据删除

`DELETE /api/account/me` 只允许普通登录用户删除本人账户，管理员账号拒绝自助删除。服务端显式删除无级联保障的账户表记录，并依靠外键级联清除其余账户数据；同时清理 Backend 账户媒体、STT 音频归档和失败上传恢复目录。Android 在服务端成功后清空 Room、本地录音/附件/导出缓存、会话、令牌与 owner 标记，再回到登录页。

## OTA

Lite 基线版本为 `1.2.72 / 10272`；本次云端启动预检重试补丁发布为 `1.2.73 / 10273`，固定签名 release 构建后使用 `server/deploy-remote.ps1 -WithBackend -AndroidApk` 原子发布，仅保留最新版本与上一版本。生产元数据、APK Range、云端 STT 健康检查和 systemd 服务状态需在发布后复核。

## 云端启动预检

移动网络或 IPv4 中继可能在一次短 HTTPS 健康检查中返回 reset。Android 现在对连接异常和 502/503/504 做最多三次、递增 350 ms 间隔的短重试；401/403、额度不足和配置错误立即返回，不会被重试掩盖。

## 2026-09-11 继续修复

实测发现 `lstwin.space` 的 IPv4 TLS 握手在 Nginx ECDSA 证书上报 `bad key share` 并被 reset，IPv6 正常、IP 证书入口正常；请求尚未进入账户或 STT 鉴权层。因此 Lite `1.2.76 / 10276` 的账户、云端 STT、Agent 和 OTA 默认入口统一改为 `https://118.25.43.185`，仍使用 HTTPS、账户短期 token 和服务端用户隔离。`lstwin.space` 保留给本地模型 IPv6 入口，不删除 DNS 或停用服务。

验证：服务端账户/STT 测试 89 项通过；Android 定向单测、Kotlin 编译和固定签名 release 构建通过。发布后需再次验证 `/api/app-update/android/light`、APK SHA-256、`/stt-cloud/health` 与 WebSocket 首包。
