# STT 本地/云端分段切换与模型基线（2026-08-21）

## 结论

录音页“实时转录”标题右侧提供紧凑的“云端 / 本地”分段控件。控件选择会调用既有 `switchSttEngine`，因此同时改变持久化配置和录音中的实时流式服务，不是仅改变显示文案。

- **本地**：Faster-Whisper 本地主引擎；本地连接或连续推理失败时，按现有快速故障转移流程切换腾讯云。
- **云端**：腾讯云实时识别主引擎；本地服务不参与本次主链路。
- 切换期间控件禁用，状态条继续显示连接中、切换中或云端接管，避免用户误以为录音中断。
- 未录音时切换会持久化到下一次录音；录音中切换会复用 `RecordingSessionController.switchStreamingProvider`。

## 视觉与交互

控件采用 Siri “simple and effective”原则：126×34dp 胶囊、2dp 内边距、17dp 圆角，选中项使用主题蓝色填充，未选中项使用浅色透明底，分别配云朵和电脑图标。没有新增设置弹窗、长菜单或重复状态说明；高级识别语言和云端档位仍保留在“识别设置”中。

本轮重启后再次使用仓库内 60 秒中文基准音频执行真实 `/transcribe`：17.06 秒完成，输出 185 字，确认模型加载、CUDA 推理和受保护接口均可用。Windows 计划任务 `MeetingNotesApp-LocalSTT` 保持登录时启动；任务触发后模型正常加载并监听 `0.0.0.0:8888`。

本机启用系统代理时，命令行探活必须绕过代理访问回环地址，否则 `127.0.0.1` 可能被错误送往代理端口并产生“连接失败”的假阴性。Windows 启动链路现改为无代理轮询健康接口，最多等待 180 秒，只有模型真正就绪才返回成功；实测 CUDA 冷启动可能超过 90 秒，因此不能再使用固定 5 秒或 90 秒判断失败。这不影响 Android AVD 通过 `10.0.2.2:8888` 访问宿主机。

本机 RTX 3060 12GB 运行该模型属于速度、准确率和实时性的合理平衡，不在没有同一音频集实测对比前替换为完整 `large-v3`。后续若追求最终稿准确率，可增加独立的最终精修 profile；实时预览继续使用 `large-v3-turbo`，以避免明显增加延迟和显存压力。

## 优化边界

当前服务已经具备 VAD、短窗重叠、预览质量门控、连续失败快速故障转移和最终稿 beam search。下一轮优化优先验证真实录音集的输入噪声、手机麦克风增益和网络抖动，再决定是否增加 Android 端可选 NoiseSuppressor/AGC；不默认强制打开可能损伤人声的系统音效。
