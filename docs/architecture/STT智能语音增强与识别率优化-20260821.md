# STT 智能语音增强与识别率优化

日期：2026-08-21

## 目标

在保持 Faster-Whisper `large-v3-turbo` 本地优先、腾讯云兜底的前提下，提升嘈杂会议、远场人声和专有名词的识别质量，同时避免对干净录音过度处理。

## 当前架构

### Android 采集端

- `STTConfig.audioEnhancementEnabled` 默认开启，并持久化到 DataStore。
- 设置页提供单一“智能语音增强”开关，不暴露复杂音频参数。
- 开启后优先使用 `VOICE_RECOGNITION` 采集源，不支持时自动退回 `MIC`。
- 设备支持时启用 `NoiseSuppressor`；仅在 `MIC` 回退时启用 `AutomaticGainControl`。
- 不默认启用 AEC。会议录音通常没有本机扬声器回放，AEC 可能损伤正常语音。
- 停止、取消和启动失败均释放音频效果，避免音频会话泄漏。

### 实时识别

- 实时预览继续使用轻量流式推理，不执行 FFmpeg 重降噪，避免增加前置延迟。
- 会议标题作为短上下文提示随 WebSocket `start` 消息发送。
- Faster-Whisper 通过 `hotwords` 使用上下文提示，改善地名、机构名和会议主题词。

### 最终稿识别

- 本地最终稿先统一为 16 kHz、单声道、PCM 16-bit。
- 服务端分析全程均匀抽样窗口，估算噪声底、人声电平、信噪比和削波比例。
- 干净录音直接绕过降噪。
- 低信噪比时使用温和的高低通和 `afftdn`；远场过轻时追加动态增益；最后使用限幅器。
- 长录音按分段后的标准 WAV 分别分析，避免先展开整段 PCM 造成额外磁盘和等待。
- 会议标题和模板名称作为最终稿上下文提示发送，本地模型使用 `hotwords`。

## 模型决策

继续使用 `large-v3-turbo + CUDA float16 + beam 5`。

`large-v3` 的准确率可能略高，但速度和资源成本明显增加，不符合当前“快速 + 精准”的综合目标。当前优先通过采集质量、自适应预处理和上下文词汇改善识别率。

## 配置

所有服务端参数均来自环境变量：

- `STT_FINAL_AUDIO_ENHANCEMENT=1`
- `STT_FINAL_DENOISE_NOISE_FLOOR_DBFS=-48`
- `STT_FINAL_DENOISE_MAX_SNR_DB=26`
- `STT_FINAL_GAIN_SPEECH_LEVEL_DBFS=-28`
- `STT_FINAL_DENOISE_REDUCTION_DB=8`
- `STT_FINAL_AUDIO_ANALYSIS_MAX_WINDOWS=3000`
- `STT_FINAL_CONTEXT_HINT_MAX_CHARS=240`

健康接口会公开开关和阈值，但不会公开令牌或凭据。

## 稳定性

- Windows 启动脚本记录本次 STT 启动 PID。
- 模型在 180 秒内未达到健康状态时，脚本会终止本次启动的完整进程树，避免孤立进程继续占用 GPU。
- 模型加载日志区分“创建 CUDA 运行时”和“执行就绪预热”，便于判断卡点。

## 验证

- Android Debug JVM 单元测试：232 项通过。
- Android Debug APK：构建成功，固定签名校验通过。
- AVD：设置页“智能语音增强”默认开启，布局无重叠。
- Server STT 测试：65 项通过。
- FFmpeg 合成噪声音频：正确判定需要降噪并成功输出增强 WAV。
- Faster-Whisper 1.2.1：普通和批量推理接口均确认支持 `hotwords`。
- Windows 本地 STT：`large-v3-turbo / CUDA` 启动成功，连续 5 次本机健康检查通过。
- 公网 `https://lstwin.space/health`：返回增强已开启。

## 边界

- 腾讯云继续作为故障兜底；服务端自适应终稿降噪当前只作用于本地 Faster-Whisper 路径。
- 云端模式可以受益于 Android 采集端硬件增强，但导入文件走腾讯云时不额外套用本地 FFmpeg 降噪。
- 本轮未发布 Android OTA，也未修改服务器正式版本号。
