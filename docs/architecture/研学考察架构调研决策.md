# MeetingNotesApp 研学考察架构调研决策

> 文档用途：开发过程的架构镜像与决策记录。
>
> 明确边界：Obsidian 仅供开发者查阅，不属于 MeetingNotesApp 的用户功能、移动端能力、服务端接口或同步依赖。

## 已确认决策

1. 顶层会议类型只保留：通用会议、项目管理、研学考察。
2. 研学考察从“报告模板”升级为独立的 Journey 旅程模式。
3. 内容采用三层形态：StageNote 分段笔记、JourneyEdition 总游记、PublishedPost 发布快照。
4. 暂停录音、暂存本段、暂停旅程、完成旅程、发布笔记必须是不同状态和动作。
5. 旅程级图片不设人为张数上限，采用分批导入、缩略图、断点上传、失败重试和存储配额。
6. GPS 近期只做 EXIF 和事件采点，不默认持续后台轨迹；公开时支持位置降精度和删除。
7. Android 采用 Room + 本地文件作为可信来源，WorkManager/Outbox 负责持久同步。
8. 服务端近期采用模块化单体；真实规模证明需要时再迁移 PostgreSQL、引入独立搜索或推荐服务。
9. 社区只消费用户确认后的发布快照，不直接暴露原始音频、精确位置和未确认内容。
10. 蓝牙耳机和自研硬件后置，BLE 只作为独立控制面，不侵入 Journey 核心领域。

## 核心实体

`Journey`、`JourneyStage`、`CaptureSession`、`MediaAsset`、`LocationEvidence`、`TranscriptSegment`、`StageDraftVersion`、`JourneyEdition`、`PublishedPost`、`SyncOutbox`。

## 推荐路线

1. P0：回归三类模板和已有补丁。
2. P1：本地 Journey/Stage、多图任务、录音与旅程状态、事件采点。
3. P2：阶段证据提取、阶段稿、人工确认和版本快照。
4. P3：总稿合并、私密云同步和冲突处理。
5. P4：社区发布、搜索、互动、审核、位置和 AI 标识。
6. P5：普通蓝牙验证与自研 BLE 控制设备。

## P1 实施记录（2026-08-05）

### 本批已完成

1. Android Room 数据库升级至 v6：新增 `journeys` 与 `journey_stages`，并提供 5→6 显式迁移、外键级联删除、旅程与会议的一对一约束、阶段序号唯一约束。
2. 新增 `JourneyRepository`：创建旅程和首段、暂存当前段、开始下一段、暂停旅程及继续旅程均以独立状态表达；录音的暂停/继续不改变旅程状态。
3. 录音页仅在用户选择“研学考察”后，通过“更多”菜单显式提供“开始研学旅程”；普通会议不会因模板切换而被自动转换。
4. Siri 录音布局增加一条紧凑的“研学旅程 / 当前段”状态，不增加底部并列操作；“暂存本段、暂停旅程、继续旅程”均收纳在现有溢出菜单。
5. 旅程段暂存的正确顺序为：暂存当前段后不创建空白下一段，用户继续旅程时才创建下一段。

### 本批验证

- `:app:testDebugUnitTest` 全量 Android 单元测试通过（2026-08-05）。
- Journey 实体映射、仓储阶段状态机、录音页换会议时的旅程状态清理均有聚焦单元测试。
- Kotlin/KSP、Room DAO、Koin 注入和 Compose 参数链均完成编译验证。

### 下一批边界

- 2026-08-05 已开始 P2 的证据归属基础批次，详见下节；阶段稿与 AI 生成仍未进入本批。
- 本批未实现“完成旅程”、总游记版本、发布快照、社区、云同步、后台 GPS 轨迹或蓝牙设备控制。
- GPS 仍保持现有的 EXIF/事件采点辅助策略，不开启默认持续定位。

## P2-A 实施记录（2026-08-05）

### 本批已完成

1. Android Room 数据库升级至 v7：`transcripts` 与 `meeting_attachments` 增加可空 `journeyStageId`，并建立阶段查询索引；6→7 显式迁移不改写历史数据。
2. 录音、导入音频、人工文本、转写二选一和批量图片导入在事件开始时捕获当前行程段；普通会议及历史资料保持未归属状态。
3. 录音服务将行程段标识传入 WorkManager 后台转写，即使界面离开或后台任务稍后执行，最终转写仍归属录音开始时的行程段。
4. 数据仓储增加按行程段读取转写和图片的接口，为下一批生成独立 `StageDraftVersion` 提供稳定证据边界。
5. 行程状态正在落库时暂时锁定录音主操作，避免快速点击产生缺失阶段归属的研学录音。

### 下一批边界

- 下一批新增 `StageDraftVersion`，使用阶段范围内的转写、图片与位置证据生成可编辑草稿，并保留每次确认的不可覆盖版本。
- 本批不改变现有整场会议纪要生成逻辑，不自动发布内容，不引入社区、云同步、持续 GPS 或蓝牙依赖。

## P2-B 实施记录（2026-08-05）

### 本批已完成

1. Android Room 数据库升级至 v8：新增 `stage_draft_versions`，按“阶段 + 版本号”唯一索引保存 `StageDraftVersion`；阶段删除时草稿版本随外键级联删除。
2. 已暂存阶段可基于该阶段归属的转写、图片及其 GPS/EXIF 线索生成 Markdown 阶段笔记。生成仍复用既有 `LLMEngine.chat`，不会改写整场会议纪要流程。
3. 阶段稿遵循草稿/确认两态：草稿可编辑，确认操作使用条件更新，已确认版本不能再编辑或二次确认；再次生成只新增下一版本，不覆盖历史版本。
4. Siri 录音页仍将次要操作收纳在“更多”菜单：没有阶段稿时生成，有草稿时编辑，确认后查看或生成新版本；状态条仅显示紧凑的“阶段笔记待编辑/已确认”。
5. 在研学旅程已暂存、但下一段尚未开始的间隙，录音、导入音频、导入图片、保存人工文本和保存转写结果都会被阻止，确保每条研学证据都有明确 `journeyStageId`。

### 本批验证

- `StageDraftVersion` 实体映射覆盖状态、证据计数和确认时间。
- `StageDraftRepository` 覆盖首版编号、版本递增、确认后的不可编辑与不可二次确认。
- 阶段稿 Prompt 覆盖行程段、实际图片清单和“不得虚构图片编号”约束。
- Kotlin/KSP、Room、Koin 与 Compose 参数链完成编译验证。

### 后续边界

- 尚未实现 `JourneyEdition` 总游记合并、社区发布、私密云同步、搜索推荐、后台 GPS 轨迹或 BLE 设备控制。
- 当前只呈现最近一个已暂存阶段的笔记入口；完整阶段历史与总游记编排留给 P3。

## P3 实施记录（2026-08-06）

### 本批已完成

1. Android Room 数据库升级至 v9：新增 `journey_editions`，以旅程和版本号建立唯一约束，并保存总游记引用的阶段稿 ID 快照。
2. 总游记只从每个阶段最新的已确认阶段稿生成；阶段稿仍处于草稿状态时不会进入总游记，避免未确认内容被汇总或发布。
3. 总游记同样采用草稿/确认两态：可编辑、可确认、确认后不可覆盖；再次生成会产生新版本，并记录新的阶段稿来源集合。
4. Siri 录音页新增“生成总游记、编辑总游记、查看总游记、生成总游记新版本”入口，继续复用现有“更多”菜单和简洁状态条。
5. 总游记可在旅程暂停、继续或仍处于进行中的阶段间生成，当前只作为本地编辑与确认结果，不自动完成旅程、不自动发布。

### 本批验证

- Room v9、Koin 参数链和 Compose 回调链完成编译验证。
- 总游记实体映射、仓储版本不可覆盖、Prompt 阶段顺序约束和换会议状态清理均有单元测试。
- Android 全量单元测试通过（2026-08-06）。

### 后续边界

- P4 再考虑发布快照、社区浏览互动、搜索推荐、审核和位置脱敏。
- 云同步、冲突合并、后台 GPS 轨迹、蓝牙耳机及 BLE 控制设备仍不在当前实现内。

## P4-A 实施记录（2026-08-06）

### 本批已完成

1. Android Room 数据库升级至 v10：新增 `published_posts` 本地发布快照表，快照绑定已确认的 `JourneyEdition`，并按旅程保存独立版本号。
2. 发布快照始终使用 `PRIVATE_PREVIEW` 可见性；`READY` 只表示本地发布准备完成，不代表已上传、已公开或已进入社区分发。
3. 创建快照时复制总游记正文并自动移除十进制度表示的精确经纬度；快照不包含原始音频、图片文件或 EXIF 信息，并记录坐标脱敏数量和 AI 辅助标识。
4. 发布前必须分别确认隐私检查和内容/图片权利；两项缺一不可进入 `READY`，就绪后可撤回为 `WITHDRAWN`。
5. Siri 录音页继续通过“更多”菜单提供“创建社区发布预览、发布前检查、查看预览、撤回发布准备”，不增加主页面按钮或社区仪表盘。

### 本批验证

- Room v10、Koin 和 Compose 参数链完成编译验证。
- 发布快照实体映射、双确认门槛、就绪后不可修改、撤回状态、坐标脱敏和换会议状态清理均有单元测试。
- Android 全量单元测试通过（2026-08-06）。

### 后续边界

- P4-B 才进入服务端社区接口、公开发布、个人主页、浏览列表、搜索、互动、审核和举报；届时 Android 与 Server 变更必须分批提交。
- 当前不上传任何发布快照，不提供公共链接，也不引入推荐算法、云同步、持续 GPS 或 BLE。

## 资料边界

- 51CTO 文章用于借鉴领域拆分、统一 API、消息机制和灰度迁移，不作为携程游记架构的官方证据。
- 携程公开页面说明传统长游记已转向发布笔记；本项目采用“分段笔记 + 总游记 + 发布快照”的双层内容策略。
- 小红书只借鉴封面、标签、信息流和互动，不借鉴其社交内容底层模型。
- Android 官方离线优先和照片选择器资料支持本地可信来源、持久队列和多次追加导入。
