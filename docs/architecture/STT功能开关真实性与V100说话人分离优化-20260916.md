# STT 功能开关真实性与 V100 说话人分离优化

日期：2026-09-16

## 结论

- Android 设置中的“说话人分离”与“语音增强”均持久化并传入录音链路。
- 语音增强在 Android 采集端使用系统 NoiseSuppressor/AGC；V100 文件转写增加高低通与 `afftdn` 轻度滤波，导入音频也能获得一致的基础增强。
- 模板动效开关的真实语义统一为“减少模板动效”：关闭时保留节点轻量过渡，开启时即时切换。
- V100 服务新增 sherpa-onnx 本地说话人分离加载、时间段对齐和“说话人 N”输出；实时会话停止时对完整音频做一次最终分离，实时预览仍优先低延迟。
- 腾讯云生产配置已开启说话人分离能力声明；只有响应包含真实 `speaker_id` 时才标记 active，避免伪造标签。

## 能力状态

V100 需要安装 `sherpa-onnx==1.13.6` 与两份模型：

```text
speaker-diarization/sherpa-onnx-pyannote-segmentation-3-0/model.int8.onnx
speaker-diarization/3dspeaker-eres2net-base-zh-16k.onnx
```

健康接口会同时返回 `enabled`、`models_present`、`active`、`provider` 和错误信息。开关打开但模型缺失时，服务保留普通转写并明确报告不可用，不会输出虚假的说话人编号。

## 验收边界

本轮代码和协议测试已通过。2026-09-16 已通过 V100 管理 SSH 完成增量同步：服务代码、`sherpa-onnx==1.13.6` 依赖、两份 ONNX 分离模型及私有环境开关均已部署到 `D:\LS-Project` / `D:\LS-Models`，并重启 `MeetingNotesApp-V100-STT` 计划任务；反向隧道任务未重启。

公网 `/stt-local/health` 已确认：`model_loaded=true`、`cuda=true`、`diarization.enabled=true`、`diarization.models_present=true`、`audio_enhancement.enabled=true`。真实 10 秒文件探针返回 HTTP 200 和转写文本；单人样例 `diarization.active=false` 属于正确结果（没有伪造说话人标签）。多说话人录音首次调用分离器后，`active` 才会变为 `true` 并输出“说话人 N”。

## 管理面迁移

原 Windows STT 管理页已迁移为 V100 原生管理页：`https://lstwin.space/stt-admin/`。页面及 `/admin/api/status`、`/admin/api/events`、`/admin/api/logs` 均由 V100 提供，使用独立 HTTP Basic 管理凭据；在线模型切换明确关闭，避免误触中断 FunASR 流式模型。主业务账户后台仍使用 `/admin/`。

公网链路已统一：IPv4 为 VPS Nginx，IPv6 为本机 Caddy 回源 VPS，随后经 `127.0.0.1:18889` 反向 SSH 隧道进入 V100。兼容发现接口 `/health`、`/ready` 也已指向 V100；旧 Windows 本地 STT 进程不再监听生产端口。
