# STT 功能开关真实性与 V100 说话人分离优化

日期：2026-09-16

## 结论

- Android 设置中的“说话人分离”与“语音增强”均持久化并传入录音链路。
- 语音增强在 Android 采集端使用系统 NoiseSuppressor/AGC；V100 文件转写增加高低通与 `afftdn` 轻度滤波，导入音频也能获得一致的基础增强。
- 模板动效开关的真实语义统一为“减少模板动效”：关闭时保留节点轻量过渡，开启时即时切换。
- V100 服务新增 sherpa-onnx 本地说话人分离加载、时间段对齐和“说话人 N”输出；实时会话停止时对完整音频做一次最终分离，实时预览仍优先低延迟。
- 腾讯云生产配置已开启说话人分离能力声明；只有响应包含真实 `speaker_id` 时才标记 active，避免伪造标签。

## 能力状态

V100 需要安装 `sherpa-onnx==1.13.6` 与两份模型：

```text
speaker-diarization/sherpa-onnx-pyannote-segmentation-3-0/model.int8.onnx
speaker-diarization/3dspeaker-eres2net-base-zh-16k.onnx
```

健康接口会同时返回 `enabled`、`models_present`、`active`、`provider` 和错误信息。开关打开但模型缺失时，服务保留普通转写并明确报告不可用，不会输出虚假的说话人编号。

## 验收边界

本轮代码和协议测试已通过；V100 远端主机的 Windows SSH 管理入口当前不可用，因此新增的 V100 分离代码和依赖已入库，但仍需在 V100 主机执行一次服务更新/重启后，才能把公网 `/stt-local/health` 的 `models_present` 与 `active` 更新为真实状态。当前 Ubuntu 生产 STT 已确认本地 sherpa-onnx 模型存在，腾讯云能力声明已生效。
