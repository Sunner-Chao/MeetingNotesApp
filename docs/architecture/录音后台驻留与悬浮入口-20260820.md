# 录音后台驻留与悬浮入口

日期：2026-08-20
本轮复核：2026-08-22

## 决策

进行中的录音是全局唯一、由前台服务拥有的会话。离开录音页、回到首页、进入其他 App 或回到手机桌面均不改变其录音状态；录音页只提供开始、暂停和继续。暂停会话不再占用麦克风，可以安全暂存并交接给下一条会议；用户仍可返回原会议继续，或在暂停后明确选择“生成会议纪要”完成收尾。

## 交互规则

- 录音页左上角返回和系统返回仅回到工作台，不暂停也不停止录音。
- 首页在已有未暂停录音时不创建新的普通会议记录，提示“会议名正在记录，请先暂停后再开始新记录。”，可直接回到当前录音。
- 首页发现已有暂停会话时允许创建并开始新会议。服务会先固化旧会议的 WAV、实时文本和累计时长，将其保留为“未完成记录”，释放麦克风后再启动新会议；控制器无法完成 WAV 暂存时会恢复旧暂停状态并拒绝新会议。
- 当前会议在“最近记录”置顶，用 Fluent 蓝色细框与低频呼吸动画标注，并显示“录音中”或“已暂停”。
- App 退到后台后，若用户在设置中开启悬浮球且授予系统悬浮窗权限，则显示悬浮球。点击只回到当前录音，悬浮球不提供暂停、继续或结束，避免误触。
- 录音页中央麦克风是唯一的录音控制：未开始显示“开始”，录音中显示“暂停”，已暂停显示“继续”；底部不再提供重复的暂停控件。
- 暂停后，录音页右下角的纪要图标可用。该操作是唯一的收尾入口，内部完成保存、转写和生成；右上角菜单不再放置生成纪要，页面不暴露“终止”“结束”或“放弃本次录音”。生成中图标显示圆形 loading，点击可取消。
- 录音前台通知只提供回到当前录音的入口，不提供直接结束、暂停或继续动作。

## 实现边界

- `RecordingService` 与 `RecordingSessionController` 继续持有麦克风、实时 STT 和会话状态；本次没有改变本地 STT 优先和腾讯云兜底策略。
- `MainActivity` 在后台时依据悬浮球设置和会话状态显示入口，并通过显式 `meetingId` 将悬浮球/通知点击导航至正确会议。
- 首页只订阅已有的 `RecordingSessionController.state`；不会新增 Room 表、字段或迁移。
- 强制停止 App、系统强杀前台服务或厂商极端省电策略仍可能中断录音，不能视作普通的前后台切换。
- 暂停交接会把每一段录音写入 `meeting_audio_segments`，旧会议跨多个片段继续录音时按 `sequenceNumber` 合并为稳定的 `meeting_<id>.wav`；原始片段仍保留，恢复任务会将片段路径视为已归属素材。
- 会议仓储或转写持久化出现异常时，服务会记录保存错误；已生成的 WAV 仍留在应用私有录音目录，后续应补充可重试的交接恢复任务。

## 验收重点

1. 录音中从左上角返回后，首页当前记录显示蓝框；再次点击可回到同一会话。
2. 未暂停录音期间点击“开始记录”，不产生额外待完善会议并显示体贴提示。
3. 点击暂停后回到首页，能够新建并开始另一条会议；旧会议在最近记录中显示“已暂停/未完成”。
4. 暂停交接完成后，旧会议的音频文件和实时文本仍可重新打开；若控制器无法完成 WAV 暂存，新会议不启动。
5. 回手机桌面后，录音和实时转写持续；开启悬浮球时点击可回到同一会议。
6. 点击暂停后，右下角纪要图标可用；生成过程显示 loading，点击同一图标可取消，生成过程开始后悬浮球和前台通知消失。
