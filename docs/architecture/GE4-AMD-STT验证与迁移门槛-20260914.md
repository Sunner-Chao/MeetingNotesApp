# GE4 AMD STT 验证与迁移门槛

日期：2026-09-14

> 2026-09-15 状态更新：用户明确取消 Windows CUDA 本机节点，已停止其 STT 进程并禁用 `MeetingNotesApp-LocalSTT` 自启动。后续本地 STT 仅评估 GE4 AMD，云端继续使用腾讯云。详见 [[GE4实时预览实测与本机STT停用-20260915]]。

## 设备

- GE4：Windows 7 SP1，Intel i5-650，8 GB RAM
- GPU：AMD Radeon HD 7800 / Pitcairn，1 GB VRAM
- 驱动：AMD APP OpenCL 1.2
- Vulkan：实际调用返回 `VK_ERROR_INCOMPATIBLE_DRIVER`

## 验证结论

1. OpenCL 基础内核可以执行，AMD GPU 不是不可用。
2. 普通 device buffer 在 1 MB 传输测试中出现可复现位错误；`CL_MEM_ALLOC_HOST_PTR` 锁页路径传输校验通过。
3. 旧实验构建的默认 GEMM 约 29 秒处理 25～30 秒音频，但输出为乱码/感叹号，不能用于生产。
4. CPU 路线输出基本可读，但已存日志对应 30.0 秒 `project-30s.wav`，耗时约 125.8 秒（原先摘要将其误记为 25.3 秒），不能满足实时要求。
5. 强制 CLBlast direct GEMM、顺序队列与锁页内存后，四组矩阵抽样数值校验通过；完整 base Q5_1 转写 25.3 秒受控中文用时 21.89 秒，输出可读但有明显词语错误。SSH PowerShell 输出读取曾超时，经远端日志确认不是模型推理超时。
6. 2026-09-15 已确认：之前 CLBlast 对象文件早于锁页补丁。完整重编译后，锁页内存下默认 GEMM 的四组矩阵抽样测试无误差；base Q5_1 整段转写降到 17.18 秒。旧乱码结果不能据此认定该 GPU 无法计算 STT。

## 2026-09-14 历史策略（已被 09-15 用户要求替代）

- 不将 GE4 接入生产 STT，不修改 Android 默认地址，不关闭 Windows 本机 Faster-Whisper 服务。
- Windows 本机 Faster-Whisper `large-v3-turbo + CUDA` 继续作为当前本地主链路，腾讯云作为既有兜底。
- GE4 仅保留在 `tmp/ge4-build` 与 `D:\MeetingNotes-STT-Lab` 的隔离实验环境中。

## 后续可行路线

1. 优先验证现有系统下的正确构建与 base/small 模型；升级操作系统需要单独授权，且升级不保证显存问题解决。i5-650 不符合 Windows 11 官方 CPU 支持要求，不能直接推荐升级 Windows 11。未来可评估受支持的 Linux 系统及 AMD 驱动。
2. 如果必须保持 Windows 7，则继续优化 CLBlast Pitcairn 的 direct kernel，并以完整中文样本进行“正确率、实时倍率、长音频稳定性”三项验收。
3. 只有在连续样本无乱码、数值校验通过、实时倍率达到目标后，才部署 GE4 STT 管理服务和公网域名。

## 验收门槛

| 项目 | 门槛 |
|---|---|
| 正确性 | 中文受控样本无乱码，关键实体可读 |

| 速度 | 实时倍率不低于 1.0，最好达到 1.5 |
