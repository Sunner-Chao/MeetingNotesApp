# 录音标记与研学分段自动化

## 目标

在录音进行到关键节点时，用一次“标记”同时建立录音时间、转录文字和现场图片之间的明确关系；在研学考察场景中，用录音的开始、暂停和继续自然驱动旅程分段，减少额外操作。

## 图文标记链路

1. 用户点击左下角“标记”；右上角不再保留重复的独立“会议图片”入口。
2. 系统以当前录音时长创建 `RecordingMarker`，并提取最近一句转录作为 `transcriptAnchor`。
3. 锚点文字立即在实时转录中显示为红色，界面进入“待配图”状态。
4. 标记建立后立即呼出来源选择、摄像头或相册，并把明确的 `recordingMarkerId` 传给导入流程。
5. 图片附件保存同一标记 ID、录音时间、文字锚点和可选的 `journeyStageId`。
6. 至少一张图片导入成功后，当前标记自动闭合；用户取消选择时保留标记，允许稍后重试。

该链路禁止通过“最近一个未使用标记”推测图片归属。关联必须使用显式标记 ID，避免连续拍摄、异步回调或多阶段记录时错配。

## 纪要生成

纪要生成前会把图片的录音时间和文字锚点作为定位提示附加给 Agent。提示只用于决定图片在正文中的插入位置，不视为新的事实材料。DOCX/PDF 导出继续使用现有图片占位与结构化渲染能力，在与锚点语义对应的段落附近插入图片。

当整场转录和研学阶段快照同时存在时，整场未分段转录是会议纪要的规范来源；阶段快照只服务于阶段笔记，避免同一段发言在总纪要中重复。

## 研学考察自动分段

研学考察不再在右上角提供“开始旅程、暂存本段、开始下一段”等手工状态按钮：

- 开始录音：自动创建 Journey 和第 1 段，或续接当前有效段。
- 暂停录音：检查本段相对基线的新增文字、录音标记和图片。
- 有有效证据：自动保存当前段，不提前创建空白下一段。
- 无有效证据：视为误触或短暂停顿，继续沿用当前段。
- 继续录音：若上一段已保存，自动创建下一段并继续记录。
- 结束录音：按同样规则收束当前段。

阶段转录只保存相对上个阶段基线的增量内容。暂停或结束发生时，ViewModel 会立即冻结当前段的 ID、累计转写、录音时长、标记数和图片数；后续异步保存只消费这份不可变快照。即使用户在上一段保存完成前立即继续录音，新发言也不会被写入上一段。通知栏触发的暂停/继续进入同一状态机，并由互斥控制阶段保存与下一段创建的顺序。

## 完成页阶段时间线

研学纪要完成页直接读取 `JourneyRepository` 中的真实 `JourneyStage`，不再仅根据图片附件反推阶段：

- 有转写或标记但没有图片的有效阶段仍会显示。
- 按真实 `sequenceNumber` 排序，展示阶段标题、记录中/已暂存状态、开始或保存时间及影像数量。
- 不截断阶段数量；超出横向空间时只在阶段时间线内部滚动，避免撑高或挤压纪要主体。
- 点击阶段节点可查看该段状态、时间、影像/地点统计和可选中复制的阶段转写；图片浏览与删除继续由统一照片卡片承担。
- 阶段详情同时显示按标记时间排序并去重的文字锚点，可从“查看本段影像”进入过滤后的统一图库，核对文字与照片关系。
- 旧数据缺少 Journey Stage 时，才回退到按附件阶段 ID 聚合的兼容展示。

## 音频边界

Journey Stage 是内容组织边界，不是音频文件边界。暂停和继续只暂停/恢复同一个录音会话，整场会议默认只生成一份完整 WAV 音频；阶段信息通过时间戳、文字锚点和 `journeyStageId` 关联，不拆分或复制音频。

## 状态与失败处理

- 标记保存失败：撤销本次内存标记并提示错误，不打开媒体选择器。
- 图片选择取消：保留红色文字锚点和“待配图”状态。
- 图片导入失败：已成功图片继续保留，失败项聚合为一次提示；显式图文标记只有在至少一张关联图片成功后才闭合。
- 批量图片导入：逐张顺序复制，不把原图批量解码到内存；界面显示完成数并锁定重复入口，切换会议时取消旧任务。
- 系统页面重建：相机 URI、相册/位置权限待处理 URI 和显式标记 ID 使用可保存状态，返回后仍归属发起时冻结的会议阶段。
- 暂停时没有新增证据：不创建空阶段。
- 自动保存阶段失败：保留当前阶段并提示错误，不静默进入下一段。

## 实时预览与会议隔离

- 快速会议每次创建独立 UUID；录音控制器残留状态只有在 `meetingId` 匹配且会话仍处于启动、录音或停止过程时才能恢复到页面，新会议不会接收上一场最后一条 `streamUpdate`。
- 智悟本地通用模型采用滚动音频窗口近实时识别。首轮达到 `STREAM_MIN_AUDIO_SEC` 后即可推理，后续使用 `STREAM_STEP_SEC`；两个参数继续由服务端环境动态配置。
- 智悟增强云模型走 WebSocket 实时识别；Android 默认每 120 ms 最多刷新一次界面，实际文字到达速度仍取决于识别服务返回频率和网络。
- 活动录音只渲染最近 `TRANSCRIPT_PREVIEW_MAX_CHARS` 字符，避免长转写在每次流式事件时重新排版整篇内容；完整文本不截断，停止录音后恢复完整显示与选择复制。

## 关键实现

- `RecordingMarker.kt`：标记领域模型。
- `RecordingViewModel.kt`：标记生命周期、媒体请求、研学阶段自动切换和证据判断。
- `RecordingScreen.kt`：摄像头/相册回调携带显式标记 ID。
- `MeetingAttachmentStore.kt`：顺序导入、协程取消检查及逐张进度回调。
- `SiriRecorderLayout.kt`：红色锚点与“待配图”状态。
- `GenerateReportUseCase.kt`：将图片定位标记注入纪要上下文，并选择规范整场转录。
- `RecordingService.kt`：同一录音会话内暂停/继续，保持单一音频文件。
- `ReportViewModel.kt`：加载会议对应的真实 Journey Stage。
- `ReportReferenceLayout.kt`：渲染完整阶段时间线及无图阶段。

## 视觉决策（1.2.17）

- 全局主题采用 Microsoft Fluent 蓝与中性灰；多色炫彩仅保留语义状态色，不用于主背景、卡片或主进度。
- 会议模板使用固定 2×2 自适应网格，一屏展示通用会议、项目管理、论坛会议和研学考察，点击选择，长按查看说明。
- 处理进度使用与容器同一圆角路径的细线环绕轨迹；轨迹贴合卡片边界，短尾迹使用同色透明度层次，不再使用突出的白色粗光头。
