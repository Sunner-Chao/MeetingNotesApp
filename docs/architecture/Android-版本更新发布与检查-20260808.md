# Android 版本更新发布与检查

## 目标

以轻量方式完成 Android APK 的服务端发布、登录后检查和用户可控升级。更新检查不阻塞登录，网络异常静默跳过。

## 客户端行为

- 应用进入前台时检查一次，覆盖冷启动和返回应用的场景。
- 账号会话从未登录切换为已登录时立即检查一次，覆盖应用内登录而不重建 Activity 的场景。
- 可选更新提供“立即更新、稍后提醒、忽略此版本”；忽略只针对同一 `version_code`，新版本仍会提示。
- 强制更新不能被忽略。
- 下载后校验服务端提供的 SHA-256，再调用系统安装器。

## 服务端发布

- `server/config/app-update.json` 是发布元数据来源，必须有正确的 `version_code` 和 `version_name`。
- `deploy-remote.ps1 -WithBackend -AndroidApk <apk>` 计算 APK SHA-256，并调用 `publish-android-update.sh`。
- APK 以 `ZhiWuBen-Android-<version_code>.apk` 保存。新 APK 先落盘并校验，最后原子替换 manifest；失败时旧 manifest 不变。
- 默认保留当前和上一版本，清理更早 APK 与旧的固定文件名包。版本化下载地址使用户在发布切换瞬间仍可获取已看到的上一版本。

## API

| 路径 | 用途 |
|---|---|
| `GET /api/app-update/android` | 返回当前发布版本和版本化下载 URL；未发布时为 204 |
| `GET /api/app-update/android/apk/{version_code}` | 下载当前或仍在保留期内的 APK |
| `GET /api/app-update/android/apk` | 兼容旧客户端，下载当前 APK |

## 发布前检查

1. Android `versionCode`、`versionName` 与 manifest 保持一致。
2. 使用正式签名 APK，确认签名证书没有变化。
3. 运行 Android 单元测试和 `assembleDebug` 或正式渠道构建。
4. 发布后访问元数据接口，确认版本号、SHA-256 和下载均正确。
