# STT 说话人分离：本地优先与腾讯云兜底

日期：2026-08-21

## 结论

说话人分离已接入最终转写链路，目标输出为：

```text
说话人 1：……
说话人 2：……
```

实时预览仍以低延迟为优先，不等待声纹聚类；录音文件转写、实时会话最终化和云端失败后的本地兜底按开关执行。

## 路由与模型

1. Android 设置中的“说话人分离”默认开启，并随文件转写与 WebSocket `start` 消息传递。
2. 本地最终稿先使用 Faster-Whisper `large-v3-turbo` 生成带时间段文本，再使用 sherpa-onnx 进行声学分段和声纹聚类。
3. 本地模型不可用时，已有腾讯云链路接收同一 `speaker_diarization` 参数；云端响应中的 `speaker_id`、时间段和最终文本向 Android 透传。
4. 超长录音分段转写时保留分段偏移，合并后的说话人时间段仍对应原始录音时间线。

## 本地模型

模型目录由 `STT_MODEL_ROOT` 指定，Windows 当前目录为 `D:\pro_sunner\demo_vscode\models`：

- `speaker-diarization/sherpa-onnx-pyannote-segmentation-3-0/model.int8.onnx`
- `speaker-diarization/3dspeaker-eres2net-base-zh-16k.onnx`

服务端仅在首次使用时懒加载分离器。模型缺失、采样率不匹配或 ONNX 运行失败会进入既有失败处理，不伪造说话人标签。

## 输出规则

- 连续相同说话人的文本合并为一行。
- 原始声纹编号只用于内部排序，展示层按首次出现顺序重新编号为“说话人 1、说话人 2……”。
- 未获得有效声纹时保留普通转写文本，并在 `diarization.active=false` 反映真实状态。
- `segments` 与 `diarization` 作为可扩展元数据保留，便于后续时间轴、标记和报告排版。

## 实测

使用仓库内四人中文样例（约 56.9 秒）并按生产 CUDA 启动顺序加载：

- Faster-Whisper `large-v3-turbo` / CUDA / float16：最终处理约 9.12 秒。
- 产生 12 个文本段、10 个声纹片段，识别出 4 位说话人。
- `diarization.provider=local-sherpa-onnx`、`active=true`。
- 服务端说话人格式化、腾讯云响应解析、超长分段偏移和旧调用签名兼容测试均通过。

## 边界

- 本轮未实现实时预览中的逐句声纹标注，以免引入前置延迟和频繁重排。
- “说话人 1”只是匿名稳定标签，不等同于真实姓名；后续可在报告页允许用户映射参会人。
- 本轮未构建或发布 Android OTA；需要发布时仍遵循固定签名和服务器 OTA 双文件保留策略。
